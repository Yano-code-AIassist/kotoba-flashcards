# kotoba — 単語帳アプリ

スマートフォンとPCで使う単語帳Webアプリです。React / Vite / TypeScript / Tailwind CSS / lucide-reactで作成しています。

**開発中のプロジェクトです。** 基本機能は実装済みで、公開版の認証・保存・スマホ実機での最終確認を進めています。GoogleログインはOAuthクライアントの作成とシークレットの保存まで進んでおり、次はRenderへの環境変数登録と実ログインの確認です（2026年11月19日時点の利用者申告）。具体的な続きは[Googleログイン設定の手順4](docs/google-public-login.md#4-renderへ設定する)を参照してください。

**アカウント・フォルダー階層対応版**です。単語帳の中にフォルダーを作り、さらに子フォルダーと単語を登録できます。メール＋パスワード、Google、LINEのログインと、アカウントごとのサーバー保存に対応しています。Google・LINEとメール配信には外部サービスの設定が必要です。単語帳の管理・一覧編集・検索・CSV入出力・スワイプ学習・途中再開も利用できます。

> 保存先はサーバーのSQLite、または設定した外部PostgreSQLです。同じサーバーへ同じアカウントでログインすると、別の端末でも利用できます。フォーム入力は「保存」を押した時点で保存します。他の端末の変更は再読み込みで反映します。以前のLocalStorageデータは設定画面から取り込めます。

## 起動する

このプロジェクトではNode.js 24を推奨します。プロジェクトのフォルダで以下を実行してください。

```powershell
npm ci
npm run dev
```

[http://127.0.0.1:5173/](http://127.0.0.1:5173/) を開き、「初めての方：アカウントを作成」から登録します。画面と認証APIが同時に起動します。初期設定はこのPC専用で、メール確認はSMTP、ResendまたはBrevoの設定後に有効になります。停止するときはターミナルで `Ctrl + C` を押します。

この環境では、npmの依存関係取得時に証明書エラーが発生しました。同じエラーが出た場合に限り、PowerShellで以下を実行してから再試行してください。現在のPowerShellセッションで、Node.jsにシステムの証明書を利用させる設定です。

```powershell
$env:NODE_USE_SYSTEM_CA = '1'
npm ci
```

証明書の検証は無効化しません。

## 使ってみる

1. ホームの「最初の単語帳を作成」を押します。
2. 名前に「基本情報技術者」と入力して「単語帳を作成」を押します。
3. 作成した単語帳の詳細が開きます。「単語を追加」から、問題「RFP」、答え「Request for Proposal」、補足「提案依頼書」を入力し、「単語を保存」を押します。
4. 単語一覧に追加した内容と「未学習」が表示されます。編集ボタンから内容を変更できます。削除ボタンでは対象の問題を確認してから削除します。
5. 下部ナビゲーションまたはサイドバーの「単語管理」から、管理する単語帳を選べます。単語一覧の選択欄から別の単語帳へ切り替えることもできます。
6. ホームや単語帳詳細から、単語帳の名前変更・削除もできます。単語帳を削除すると、その中のフォルダーと単語も削除されます。
7. ページを再読み込みします。保存した単語帳・単語が残り、同じ内容を編集できることを確認できます。

単語を追加すると、一覧・ホーム・詳細の件数に反映されます。新しい単語は未学習として登録します。ナビゲーションの「設定」から学び方を変更できます。単語帳名の入力中に閉じたり画面を移動したりする場合も、未保存の変更を破棄するか確認します。

単語帳名は必須で、前後の空白を除いて80文字以内です。同じ名前の単語帳も別の単語帳として作成できます。

## フォルダーで分類する

単語帳の詳細にある「フォルダーを作成」から、次のように整理できます。

```text
基本情報技術者
├─ テクノロジ系
│  └─ 基礎理論
│     ├─ 2進数（単語）
│     └─ 論理演算（単語）
├─ マネジメント系
└─ ストラテジ系
```

1. 「基本情報技術者」を作成し、「フォルダーを作成」で「テクノロジ系」を登録します。
2. 「テクノロジ系」を開き、同じボタンから「基礎理論」を作成します。
3. 「基礎理論」を開いて「単語を追加」を押すと、その場所に保存されます。PCは一覧内の入力行、スマホは入力フォームが開きます。「まとめて追加・CSV」から一括貼り付け・CSV取込も利用できます。
4. 上部の「基本情報技術者 ＞ テクノロジ系 ＞ 基礎理論」から上の階層へ戻れます。
5. 単語の移動ボタンから同じ単語帳内の別フォルダーへ移せます。単語の内容と学習状態を引き継ぎます。

各階層に、単語と子フォルダーを一緒に置けます。子フォルダーがある場所では「この場所の単語」を「下の階層も含める」に切り替えると、配下の単語をまとめて検索・編集できます。新しい単語の追加先は画面に表示される現在のフォルダーです。現在のフォルダーの名前変更・削除は「フォルダー設定」から開きます。

フォルダー画面の「このフォルダーで学習テスト」では、その場所の単語と子フォルダーから出題範囲を複数選択できます。単語帳詳細でも「単語帳直下」と「テクノロジ系」「マネジメント系」などの子フォルダーを組み合わせられます。選んだ子フォルダーは下の階層も対象です。フォルダーの名前変更・削除にも対応し、削除前に対象フォルダー数と単語数を表示します。

フォルダー名は1〜80文字、深さは20階層までです。以前の単語は単語帳の直下に残り、必要に応じて移動できます。この分類機能はフォルダーを作る機能です。PDF・画像などの添付機能は含みません。

保存形式と検証内容は[フォルダー機能の説明](docs/folders.md)に記載しています。

## 単語を登録する

| 単語の項目 | 必須 | 上限      |
| ---------- | ---- | --------- |
| 問題       | 必須 | 2,000文字 |
| 答え       | 必須 | 2,000文字 |
| 補足説明   | 任意 | 5,000文字 |

保存時は前後の空白を除き、内容の途中にある改行を保持します。内容を編集しても、単語のID・所属・作成日時・学習状態・最終学習日時を維持します。個別フォームのEnterは改行として使い、保存ボタンで確定します。PCのテーブル編集では、以下のキー操作を使います。

入力中に「キャンセル」や画面内リンク、ブラウザの戻る・進むで移動すると、変更を破棄するか確認します。移動をキャンセルした場合は入力を保持します。未保存入力があるときはページ更新・終了時にもブラウザの確認を要求します。保存後の移動には確認を表示しません。

## PCで一覧から編集・連続追加する

画面幅1024px以上では、単語管理を「問題・答え・補足説明・状態・操作」のテーブルで表示します。「編集」でその行の3項目を編集できます。一度に編集するのは1行です。

| 操作             | 動作                                                        |
| ---------------- | ----------------------------------------------------------- |
| Tab / Shift+Tab  | 問題 → 答え → 補足 → 保存などのボタンへ順に移動・逆順に移動 |
| 入力欄のEnter    | 現在の行を保存し、次の行の問題欄へ移動                      |
| Shift+Enter      | 入力欄内で改行                                              |
| 「保存」         | その行を保存して編集を終了。編集ボタンへフォーカスを戻す    |
| 「保存して次へ」 | Enterと同じ。最後の行の次は、新しい追加行を開く             |
| 「単語を追加」   | 一覧内に空の入力行を開く                                    |
| 「キャンセル」   | 編集を終了。未保存の変更があれば破棄するか確認              |

例えば「RFP」の問題・答え・補足をTabで入力してEnterを押すと、保存して次の単語の問題欄に進みます。追加行では保存後も空の行を開くため、「RFP」「RFI」「DNS」を続けて登録できます。日本語変換の確定操作やEnterの長押しでは保存しないようにしています。

別の行の「編集」や「単語を追加」を押して未保存の内容を置き換える場合も、破棄の確認を表示します。保存エラーでは同じ行と下書きを保持し、次へ進みません。保存中・別タブでの変更検知後は保存を停止します。削除は編集中の行を保存またはキャンセルしてから行います。

テーブル上部の「フォームで追加」では個別フォームも使えます。キー操作の説明は「入力方法・ショートカット」を開いて確認できます。1024px未満ではカード一覧と個別フォームを表示します。テーブル編集中に幅を狭めた場合は、入力欄を維持して縦に並べ、「保存」か「キャンセル」でカード一覧へ戻ります。

## 資料からAIで単語を生成する

単語の管理画面やフォルダーで「資料からAIで生成」を開くと、PDF・テキストファイルや公開URLから問題と答えを生成できます。Word・PowerPointはPDFに書き出して利用します。候補の編集・選択後に、現在の場所へまとめて登録します。APIキーが未設定の場合は準備の案内を表示します。

無料枠対応のGoogle Gemini API設定、利用条件、対応形式、検証範囲は [AI生成の使い方](docs/ai-generation.md) を参照してください。

## 検索・絞り込みと一括登録

単語管理で「検索・絞り込み」を開くと、「単語を検索」で問題・答え・補足説明を検索できます。単語が0語のときは検索ボタンを表示しません。英字の大文字・小文字と全角・半角を区別せず、スペースで区切った語をすべて含む単語を表示します。例えば `RFP 提案` は、問題にRFP、補足に提案依頼書がある単語に一致します。保存する本文は書き換えません。検索欄を閉じても条件は保持され、「絞り込み中」の表示と「条件をクリア」から解除できます。

「学習状態で絞り込み」で「すべて／未学習／覚えた／まだ」を選べます。検索との組み合わせも可能です。「条件をクリア」で全件に戻します。PCでは、絞り込んだ一覧の順に「保存して次へ」が動作します。編集中は条件の変更・一括登録・CSV出力を停止します。

「一括貼り付け」を開き、次のように入力します。

```text
RFP | Request for Proposal | 提案依頼書
RFI | Request for Information | 情報提供依頼書
SoR | Systems of Record | 記録を管理するシステム
```

1. 「プレビューを表示」で行番号・内容・追加予定数・エラーを確認します。21行以上は20行ずつ表示します。
2. エラーのある行は元の入力で修正し、再度プレビューします。エラーが1行でもあれば、全件の登録を止めます。
3. 「○語を登録する」でまとめて保存します。追加した単語は未学習になり、検索条件が解除されます。

補足は省略でき、空行は無視します。問題・答え・補足がすべて同じ単語は、追加先フォルダーの既存データと貼り付け内の両方を調べ、初期設定では除外します。比較時は前後の空白のみを除き、大文字・小文字などは区別します。重複も追加したい場合はチェックを外してください。1回500語・100万文字までです。項目内に `|` や改行がある場合はCSVを使います。

プレビューの段階では保存しません。保存失敗時は入力とプレビューを残し、登録ボタンから再試行できます。既存の学習状態・学習セッションは維持し、今回追加した単語は次の学習から出題します。

## CSVを取り込む・出力する

CSVは **問題・答え・補足の教材データ** です。フォルダー階層・学習状態・ID・日時を含む全データのバックアップではありません。取り込みでは選択中の単語帳・フォルダーに新しい未学習の単語を追加し、既存の単語を上書きしません。

「まとめて追加・CSV」を開き、「CSV取込」でファイルを選択し、文字コードと「先頭行は見出し」を確認してからプレビューします。登録の手順・検証・重複除外は一括貼り付けと共通です。CSV出力の操作も同じパネル内にあります。

```csv
問題,答え,補足説明
RFP,Request for Proposal,提案依頼書
"カンマ,を含む問題","引用符""を含む答え",補足
```

| 項目                 | 対応内容                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------- |
| 列                   | 問題・答え・補足説明の順。補足列を省いた2列も可                                                                |
| 見出し               | `問題,答え,補足説明` または `question,answer,note`。補足列名は `補足` も可                                     |
| 見出しがないファイル | 「先頭行は見出し」のチェックを外す。先頭の単語も登録対象になる                                                 |
| 文字コード           | UTF-8（BOMあり／なし）またはShift_JISを選択。出力はUTF-8 BOM付き                                               |
| 引用符と改行         | カンマ・引用符・改行を含む項目は `"` で囲む。項目中の `"` は `""` にする                                       |
| 上限                 | 1回500語・100万文字、ファイルは2MB（2,097,152バイト）以下                                                      |
| 出力範囲             | フォルダーの表示範囲に従う「選択範囲すべて」または検索・状態で絞り込んだ「表示中の単語」。保存済みの内容を出力 |

引用符・改行の扱いは[RFC 4180](https://www.rfc-editor.org/info/rfc4180/)を参考にしています。空のファイル、列・引用符の不正、読めない文字コードはエラーを表示します。取り込み時は通常の単語登録と同じく、項目の前後の空白を除きます。500語を超えるCSVを再取り込みするときは、500語以内に分けてください。

CSV出力時は、数式と解釈されやすい `= + - @`（全角も含む）で始まる内容に、引用符内でタブを付けます。アプリへの再取り込みではこのタブを除きます。表計算ソフトごとの動作には違いがあり、Excelでの実操作は未確認です。根拠：[OWASP：CSV Injection](https://community.owasp.org/attacks/CSV_Injection)。

## 保存した単語で学習テストをする

1. 単語を登録した単語帳を開きます。子フォルダーがある場合は「出題範囲」で、出題したいフォルダーを複数選択します。「単語帳直下」も個別に選べます。
2. 「カード式」または「4択問題」から出題形式を選びます。4択問題には、選択範囲内に異なる答えが4つ以上必要です。
3. 「すべて／未学習のみ／『まだ』のみ／ランダム」から出題対象・順番を選びます。対象が0語の方法では開始できません。
4. 「学習テストを始める」を押します。選択した範囲と出題順を開始時に固定します。
5. カード式ではカードをタップして答えを確認し、下部の「まだ」または「覚えた」を押します。
6. 4択問題では正しい答えを1つ選びます。正解と補足を確認して「次の問題へ」を押すと、正解は「覚えた」、不正解は「まだ」として保存します。
7. 全問終了すると今回の回答結果を表示します。「『まだ』をもう一度」では、最初に選んだ範囲の「まだ」だけを同じ出題形式で再テストできます。
8. 途中で「単語帳に戻る」を押しても回答済みの状態は残ります。「続きから学習」で未回答の単語から再開できます。ページ更新やブラウザ終了後も、保存済みの形式・選択肢・出題順・回答位置を復元します。

例えば3語を学習し、「覚えた」1語・「まだ」2語と回答した場合、結果画面は1語／2語と表示します。「『まだ』をもう一度」では最新の学習状態を使い、復習対象を決めます。

途中の学習は全体で1つです。別の学習を開始する場合は切り替えの確認を表示し、キャンセルすると元の学習を保持します。切り替えても単語ごとの学習状態は残ります。完了した結果は「結果を閉じて単語帳に戻る」か、次の学習を開始するまで保持します。

出題中に追加した単語は次の学習から対象にします。出題対象または4択の選択肢に使う単語を編集・削除すると、その回の学習は終了し、新しい学習を始める案内を表示します。再開時は問題面から表示します。

カードとボタンはTabで選択し、EnterまたはSpaceで操作できます。スマートフォンでは高さ60pxの回答ボタンを下端に配置します。

### スワイプで回答する

答えを見た後、カードの中央付近から左へスワイプすると「まだ」、右へスワイプすると「覚えた」です。「指を離すと…」が表示されたところで指を離すと保存します。離す前に元の位置へ戻せば、回答を取り消せます。

短い動き・縦や斜めの移動・複数の指・画面端からの操作は回答にしません。補足説明の領域もスワイプ回答の対象外です。長い答えは縦にスクロールして読めます。保存できなかった場合は同じ答えを表示し、スワイプまたはボタンで再試行できます。

学習画面上部の「スワイプ」でON／OFFを切り替えられます。この設定は同じアカウントの単語帳で共通になり、再読み込み後も維持します。OFFのときやマウス操作では、下部の回答ボタンを使います。設定が保存できなかった場合は切り替え前の状態を保ちます。

## 学び方を設定する

1. 下部ナビゲーションまたはサイドバーの「設定」を開きます。
2. 標準の出題方法と「スワイプで回答する」を選びます。
3. 「設定を保存」で2項目をまとめて保存します。「変更を取り消す」で変更前に戻せます。

例えば標準を「未学習のみ」にすると、次に単語帳の詳細を開いたときにその方法が選ばれます。対象が0語のときは学習開始前に別の方法を選んでください。現在進行中の学習の順序や回答位置は変わりません。

スワイプ設定は学習画面のON／OFFと共通です。OFFでも回答ボタンを使えます。設定画面では保存ボタンで確定し、学習画面のスイッチは切り替え時に保存します。

未保存のまま別画面へ移る場合は破棄を確認します。保存失敗時は選択内容を残し、再試行できます。別タブの変更を検知すると保存を停止します。

## 保存とエラー時の操作

認証済みユーザーごとに、単語帳・フォルダー・単語・学習状態・日時・設定・学習セッションをサーバーのSQLiteに保存します。保存成功ごとに `revision` を増やし、古い内容による上書きを拒否します。初期保存先は `.data/kotoba.sqlite` です。

| 状況                     | アプリの動き・利用者の操作                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| 初めてのログイン         | 空のホームを表示。設定から旧データの取り込みも可能                                             |
| 通信障害・保存失敗       | エラーを表示。入力を控え、通信回復後に再試行。保存結果が不明な場合は再読み込みで確認           |
| 別端末・タブで更新された | 保存を停止。未保存入力を控えてから再読み込み                                                   |
| ログイン期限切れ         | 未保存入力を一時保存してログイン画面を表示。同じアカウントで再ログイン後、元の画面と入力を復元 |
| 別タブでアカウント変更   | セッションを再確認。元のアカウントの内容を別アカウントへ保存しない                             |
| 不正な保存データ         | 編集を停止し、サーバー上の元データを維持。管理者による調査・バックアップからの復旧が必要       |

未保存の単語、単語帳名、フォルダー名、設定、一括登録内容、AI生成候補は、ログイン期限切れに備えて同じタブの `sessionStorage` に24時間だけ一時保存します。下書きはアカウントと入力場所ごとに分離し、保存成功または利用者が破棄したときに削除します。再ログイン後は元のURLへ戻り、該当する入力画面やダイアログを自動で開きます。

パスワードと選択したファイル本体は一時保存しません。CSVはブラウザーが読み取ったテキストを復元します。AI生成前のPDF・TXT・MD・CSVは再選択が必要ですが、生成済みの候補は復元できます。ブラウザー設定や保存容量により `sessionStorage` を利用できない場合は復元できません。

以前のブラウザー保存キー `kotoba:app` は残します。設定画面から、まだ保存データのないアカウントにコピーできます。取り込み後も元の内容は削除しません。

旧LocalStorageデータを引き継ぐ際は、以前と同じブラウザー・URLを使います。例えば `127.0.0.1:5173` と `localhost:5173` は別の保存領域です。[MDN：localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

現在の保存はサーバーのrevisionを条件にした一回のSQLで行います。別端末の変更も競合として検出します。画面を開いたままの自動上書きは行いません。詳しくは[アカウント設定](docs/account-setup.md)を参照してください。

## 安全な共有とバックアップ

プロジェクトを共有するときは、フォルダー全体を手動でZIPにせず `npm run share:zip` を使います。許可したソースだけを `.artifacts` の共有用ZIPへ収録し、`.env`、`.data`、SQLite、認証シークレット、秘密鍵、ビルド結果を除外します。作成後はZIP内の禁止ファイル・秘密らしい文字列・SHA-256を自動検証します。

アカウント、フォルダー階層、学習状態、設定を含むローカルSQLiteの完全バックアップは `npm run backup` で `.backups` に作成します。バックアップは秘密情報を含むため共有しません。詳しい作成・検証・復元方法は[安全な共有ZIPとバックアップ](docs/backup-and-sharing.md)を参照してください。
