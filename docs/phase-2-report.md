# Phase 2 実装報告

更新日：2026-09-18

Phase 1の設計に沿って、ホーム画面と単語帳の作成・名前変更・削除を実装しました。Phase 3以降の機能は未実装です。

## 1. 実装した内容

- React / Vite / TypeScript / Tailwind CSS / lucide-reactの初期構成。
- 単語帳が0冊の場合の案内と、作成済みの単語帳カード一覧。
- 単語帳名、登録単語数、覚えた数、「まだ」の数、未学習数、進捗の表示。
- 作成・名前変更フォーム。名前の必須チェック、80文字の上限、前後の空白除去。
- 対象名と登録単語数を示す削除確認ダイアログ。
- 作成後に開く単語帳詳細と、ホームへの移動。
- ハッシュURLによる画面切り替え、ブラウザの戻る・進む、存在しない単語帳の案内。
- スマートフォンの下部ナビゲーションと、PCのサイドバー。
- ダイアログのキーボード操作、初期フォーカス、入力エラーと操作完了の通知。
- 日本語変換中のEnterによる誤送信と、保存中の二重操作の防止。
- データ操作と画面を分離し、保存成功後に共有状態を更新する仕組み。

現在は `memoryRepository` による一時保存です。**ページを更新・閉じると単語帳が消える**ことを画面上に表示しています。LocalStorageへの保存はPhase 4の対象です。

「基本情報技術者」を作成すると、その単語帳の詳細へ進みます。単語追加はPhase 3で実装するため、この段階の登録単語数と進捗は0です。単語追加・学習・単語管理・設定の操作は準備中として表示しています。

## 3. 動作確認方法と結果

### 自動チェック

| 確認 | 結果 | 対象 |
| --- | --- | --- |
| `npm run build` | 成功 | TypeScriptの型確認、公開用ビルド |
| `npm run lint` | 成功 | ESLintによる静的チェック |
| `npm test` | 12件成功 | 単語帳操作5件、メモリ保存4件、進捗計算3件 |
| ブラウザでの操作・表示確認 | 9項目のシナリオ成功 | Microsoft Edgeを使った自動操作、320・390・768・1024・1440px幅での表示 |

単体テストでは、空白・文字数の検証、同名でも別IDになる作成処理、改名時のID維持、削除時の関連データ除去、メモリ保存値の保護、更新番号の衝突検出、0語・未学習・「まだ」・覚えた数の進捗計算を確認しました。関連単語と学習セッションの削除はテスト用データで確認しており、単語登録・学習画面を実装したことを意味しません。

ブラウザ確認では、初回0冊、空欄・空白入力、作成・改名、戻る・進む、削除の確認とキャンセル、Tab / Shift+Tab / Escape、連続送信の重複防止、削除後のフォーカス、80文字の名前、再読み込み時の初期化、不正なURLからの復帰を確認しました。所定の表示幅で横スクロールがなく、ブラウザの実行エラー・コンソールエラーもありませんでした。LocalStorageへの書き込みがないことも確認しています。

画面幅の変更とIME確定イベントはブラウザ上の検証です。実機のソフトウェアキーボードやタッチ操作は今回の確認対象に含めていません。

確認用のスクリーンショットは `.artifacts/` に保存しています（作業用のためGit管理対象外）。

### 手動確認手順

1. `npm ci` と `npm run dev` を実行し、表示されたURLを開く。0冊の案内と一時保存の説明を確認する。
2. 「最初の単語帳を作成」を押す。空欄や空白だけで送信し、エラーと入力欄へのフォーカスを確認する。
3. 「基本情報技術者」を作成し、0語の詳細へ移動すること、完了通知が出ることを確認する。
4. ホームに戻り、カードの名称・0語・進捗0％を確認する。複数冊を作成し、一覧を確認する。
5. 名前を「基本情報技術者 午前対策」に変更し、一覧と詳細の両方に反映されることを確認する。
6. 削除ダイアログで対象名を確認する。一度キャンセルして残ることを確認し、もう一度開いて削除する。削除後の本文フォーカスも確認する。
7. Tab / Shift+Tabでダイアログ内を移動し、Escapeで閉じる。作成時は入力欄、削除時はキャンセルが初期フォーカスになることを確認する。
8. 日本語変換の確定Enterだけでは作成されないことと、作成・削除ボタンを連打して重複操作が起きないことを確認する。
9. ブラウザの戻る・進むでホームと詳細を移動する。`#/decks/missing` を開き、「見つかりません」とホームへの戻り先を確認する。
10. 横幅320px、768px、1024px以上で確認する。横スクロール、長い単語帳名の折り返し、下部ナビと本文の重なり、PCサイドバーへの切り替えを確認する。
11. 最後にページを更新し、一時保存データが消えることを確認する。詳細URLを開いたまま更新した場合は「見つかりません」からホームへ戻る。

実機の日本語入力やタッチ操作は、対象のスマートフォンでも上記手順を確認してください。

## 4. 次のPhase

Phase 3では、選択した単語帳への**単語の追加・編集・削除**を実装します。問題・答え・任意の補足を入力するフォームと単語一覧を作成し、空欄チェック・削除確認・更新後の件数表示を整えます。

引き続きメモリ保存で動作を確認し、LocalStorage保存はPhase 4で追加します。**ユーザーの確認を待ち、承認後にPhase 3へ進みます。**

企業向けの応用例としては、「基本情報技術者」の学習用単語帳を社内研修で使うことが考えられます（推測。特定企業での導入実績を示すものではありません）。
