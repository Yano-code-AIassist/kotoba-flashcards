# Phase 6 実装報告

実施日：2026年9月18日

## 1. 実装した内容

### タップ・スワイプ・回答ボタン

答えを表示した後、左スワイプで「まだ」、右スワイプで「覚えた」を記録します。下部の回答ボタンも引き続き使用できます。

移動中は矢印・文字・背景色で方向を示します。「指を離すと『覚えた』」などの表示後に指を離すと確定します。指を戻してから離せば回答しません。カード全体を画面外へ飛ばす演出は使わず、本文を最大16pxだけ動かします。OSの動きを減らす設定では本文を動かしません。

例えば「RFP」の答えを見て右へ動かし、案内を確認して指を離すと「覚えた」が保存され、次の問題を表示します。保存失敗時は同じカードの答えを維持し、スワイプ・ボタンで再試行できます。

### 誤操作を防ぐ条件

- 問題面では回答せず、答えを見てから開始した操作だけを受け付けます。
- 横方向に80 CSS px以上、かつ縦方向の1.5倍以上動いた場合に確定します。
- 10px以上の動きで方向を判定し、縦・斜めに動き始めた操作は途中から横へ曲がっても回答にしません。
- 画面の端24px以内からの動き、複数指、補足説明の領域、マウスのドラッグを回答にしません。
- 指の操作中断、ポインター取得の解除、ウィンドウのフォーカス喪失・サイズ変更、スクロール、ページ非表示時には操作を中断します。
- 保存中や別タブでの変更検知後は回答を止めます。スワイプとボタンは同じ保存処理を使います。
- スワイプ直後のクリックが、次の問題をめくったり結果画面のボタンを押したりするのを防ぎます。新しいタップ・キーボード操作は受け付けます。

距離や角度は本アプリの設計値です。実機での使いやすさを見て調整できるよう、判定を `swipeGesture.ts` に分離しました。

タッチ入力を使ったEdge検証では、連続操作時にpointerup後のclickが発行されない場面がありました。このため、動きがないタップはpointerupでも答えを表示します。従来のclickによるマウス・キーボード操作も維持します。

### ON／OFF設定とモバイル表示

学習画面に「スワイプ」の切り替えを追加しました。設定は同じブラウザー内で共通です。単語・学習中の回答位置を変えずに保存し、再読み込み後も維持します。設定の保存失敗時は変更前の値を保ち、エラーを表示します。

スマートフォンでは学習中のブランドヘッダーを省き、高さが小さい画面では余白も減らしました。回答ボタンの高さ60px、設定切り替えの高さ44px、戻るリンクの高さ44pxを確保します。長文は高さで切り詰めず、縦スクロールで読めます。固定ボタンの下に本文の末尾が隠れ続けないよう、下部の余白を確保しました。画面の切り欠き用のsafe-area余白も指定しています。

`touch-action: pan-y pinch-zoom` によって、回答カードでも縦スクロールとピンチ拡大をブラウザーに許可します。通常のカードには `manipulation` を指定しています。仕様確認：[MDN：touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)、[MDN：Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)、[MDN：setPointerCapture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)。

### 手動で試す手順

1. 単語を2語以上登録した単語帳で「学習を始める」を押します。
2. 問題面を軽く横へ動かしても回答されないことを確認し、タップして答えを表示します。
3. カード中央付近から左へ動かし、「指を離すと『まだ』」の表示で指を離します。次の問題へ進むことを確認します。
4. 次の答えで右へ動かし、「覚えた」も試します。短い動きや、途中で元の位置へ戻す操作では進まないことを確認します。
5. 学習中の「スワイプ」をOFFにし、下部ボタンで回答します。ページを再読み込みし、OFF設定と学習の続きが残ることを確認します。
6. 長い答え・補足を縦にスクロールし、意図せず回答されないことを確認します。
